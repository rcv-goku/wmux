# CLI offline conformance (W1-2c)

Covers: `cli-global-options`, `cli-no-socket-help-probes`, `cli-help-command-topics`,
`cli-version-command`, `cli-guide-skill-command`, `agents-guide-skill-cli`, `cli-docs-command`,
`cli-welcome-command`, `cli-focus-default-detection`, `cli-id-format-output`.

## Behavior

- **Grammar.** `cmux [--socket <pipe>] [--password <pw>] [--window <id|ref|index>] <command>
  [options] [--json] [--id-format refs|uuids|both] [--] [args]`. `--socket`, `--password` and
  `--window` are global only before the command; after it they belong to the command (an unknown
  option there is a usage error, exit 2). `--json` and `--id-format` work before or after the
  command and print identical output. `--` ends option parsing: `--help`, `--version`, `--json`
  and `+text` after it are payload. An invalid `--id-format` fails with
  `--id-format must be one of: refs, uuids, both` (exit 2).
- **Offline commands.** `help`, `--help`/`-h`, `help <topic>` (start, agents, navigate, inspect,
  customize, automation, browser, remote, diagnostics; anything else prints the top-level usage),
  `version`/`--version`/`-v` (`cmux <version> (<build>) [<commit>]` and its degraded forms;
  `version --help` prints the version, as in cmux), `guide`/`--skill` (embedded Markdown,
  `--json` gives `{topic, format: "markdown", content}`, extra arguments exit 2), `docs [topic]`,
  `welcome`, and `<command> --help` for every command run without contacting the app, whatever
  the socket options and environment say.
- **Branding.** Run as `wmux` (or with `WMUX_ARGV0=wmux`), every help and usage text says `wmux`;
  the first help line is `wmux - control wmux via named pipe`.
- **Focus default.** UI-opening commands accept `--focus`, `--focus <true|false>`,
  `--focus=<bool>` and `--no-focus` (last wins; nothing after `--` counts; a bad value prints
  `--focus must be true|false`). Without a flag they focus only when stdin and stdout are both a
  console and no coding-agent marker is set (`CLAUDECODE`, `CLAUDE_CODE`, `CLAUDE_CODE_ENTRYPOINT`,
  `CLAUDE_CODE_SESSION_ID`, `CODEX_CI`, `CODEX_THREAD_ID`, `CODEX_SESSION_ID`, `CODEX_SANDBOX`,
  `CODEX_MANAGED_BY_BUN`, `OPENCODE`, `OPENCODE_PORT`, `OPENCODE_SESSION_ID`, `AI_AGENT`,
  `CMUX_AGENT_*`). `WMUX_FOCUS_NEW`/`CMUX_FOCUS_NEW` = `1`/`0` force the default.
- **Handles.** `--id-format refs` (default) drops `id`/`<kind>_id` next to their refs, `uuids` drops
  the refs, `both` keeps all; text handles print the ref, the UUID or `<ref> (<uuid>)`. `rpc`
  prints the raw response unless `--id-format` is given.

## Windows notes and deviations

- "Unix socket" reads "named pipe" in help text.
- cmux's cloud, VM, account, coderouter, feedback and glaeda families are not claimed (G2,
  Appendix E D19): they exit 2 with `not supported on wmux (requires cmux cloud/macOS)`, also for
  `--help`, so the corresponding contract probes are adapted (see the CLI page).
- Client-side usage errors exit 2 (Appendix E D30).
- Display sanitization (Appendix E D24) is a framework helper (`output.writeDisplay`); families
  adopt it.
