# Session v3 core (W1-7a)

wmux saves the whole app (every window, workspace, group, pane and tab) in one session file and
restores it the next time it starts. This page covers the core: the file, the autosave and the
full saves, restore on launch, crash protection, the one-time migration of the old session file,
window placement and working directories. Scrollback replay, "Restore Previous App Launch",
corrupt-file recovery tests and the `session` CLI commands come with W1-7b.

## Files (`STATE\session\`)

`STATE` is `WMUX_STATE_DIR` when set, else `%LOCALAPPDATA%\ghostty` (the channel-aware layout of
Appendix G arrives with W1-1).

| File | What it is |
|---|---|
| `session.json` | the current session (schema `wmux-session`, version 3, ARCHITECTURE.md ADR-9.2) |
| `session.json.bak` | the previous `session.json`, kept by every save (`ReplaceFileW`) |
| `session.json.tmp` | the save in progress (written, flushed, then swapped in) |
| `session.running` | `{pid, process_start_filetime}` while wmux runs; left behind by a crash |
| `session.restoring` | exists while a restore runs (crash-loop guard) |
| `session.crashed-<ms>.json` | a snapshot whose restore did not finish |
| `session.unusable-<ms>.json`, `session.schema-v<N>.json` | an unreadable or newer-schema `session.json`, set aside |
| `STATE\run\handles.json` | the handle reservations (`window:N`, `surface:N` refs are never reused, even after a crash) |

## When the session is saved

- **Autosave:** every 8 seconds wmux serializes the session and compares it with the last save
  (volatile fields such as the save time are ignored). It writes only when something changed:
  an idle wmux never writes, a busy one writes at most once per 8 seconds. Writes happen on a
  background thread; a crash always leaves the old or the new file, never a torn one.
- **Full save:** closing the last window, and Windows logoff or shutdown (the save runs before
  Windows ends wmux; the shutdown screen shows "Saving wmux session"). Closing one of several
  windows does not overwrite the session with that window alone: the next autosave simply drops
  it. (The full save on the `quit` action needs CCR W1-7a-1; until then a quit keeps the last
  autosave, at most 8 seconds old.)
- The explicit legacy `session-save` command (`wmux +session save`) still writes the old
  `session-state.json` until W1-7b moves it to `session.json`.

## Restore on launch

wmux restores the saved session when it starts, unless:

- `WMUX_DISABLE_SESSION_RESTORE` or `CMUX_DISABLE_SESSION_RESTORE` is set;
- the `wmux.session.restoreOnLaunch` setting is `false`;
- it was started with something to open (a path or URL argument, `-e`, `--command`,
  `--working-directory`);
- it is a test instance (`WMUX_TEST_MODE`) without `WMUX_TEST_SESSION_RESTORE=1`;
- the previous restore did not finish (`session.restoring` is still there): that snapshot is
  renamed `session.crashed-<ms>.json`, a notice says so (`session.crashed`), and the launch after
  this one restores normally again.

What comes back: every window at its saved position and size (fitted into the work area of its
monitor, or of the nearest one when that monitor is gone; maximized windows maximized), the
sidebar visibility, workspace titles, descriptions, directories, pins, groups and the selected
workspace, every split with its ratio (within 1%), the focused and zoomed pane, every tab with
its title and the selected tab of each pane, and feature data stored under `ext` (keys this
build does not know are kept and written back unchanged).

Identities survive: windows, workspaces, groups, panes and tabs keep their UUIDs and refs, and
each terminal is started with its saved surface UUID (`CMUX_SURFACE_ID`, once W1-3 exports the
terminal environment).

The terminals of the workspace each window shows start first; the others follow one every
30 ms, so a large session does not start dozens of shells at once.

## Working directories

Each terminal saves the directory its shell last reported (OSC 7, or OSC 9;9 with shell
integration). On restore a terminal opens in its saved directory; if that directory is gone,
in the workspace's directory; if that is gone too, in `%USERPROFILE%`. A restored terminal whose
shell never reports a directory keeps the one it was restored in. When the shell reports a new
directory for the tab you work in, it also becomes the workspace's directory, which new tabs
inherit (once CCR W1-7a-1 routes the `.pwd` action to `meta.api.onPwd`).

## Migration from the old session file

When no v3 file exists, wmux converts `%LOCALAPPDATA%\ghostty\session-state.json` (v2, or the
older v1) once: everything goes into window 0 (with the old `window-state` geometry), each
workspace keeps its name, directory and splits, each tab its title and directory, browser tabs
come back as browser tabs at `about:blank`. The old file is renamed
`session-state.json.migrated`. The explicit legacy `session-restore` command reads the old file
the same way and restores it into window 0, replacing its workspaces; every workspace keeps its
splits (the old restore lost background workspaces and their splits).

## Settings

| Key | Default | |
|---|---|---|
| `wmux.session.restoreOnLaunch` | `true` | restore the previous session when wmux starts (restart to apply) |
| `wmux.session.autosave` | `true` | save automatically (restart to apply); off keeps the file as it is |

cmux has no settings for this (it restores unless `CMUX_DISABLE_SESSION_RESTORE` is set), so
both live under `wmux.session`.

## Windows deviations

- Windows can relaunch wmux after an update or a restart-capable reboot
  (`RegisterApplicationRestart`, not in test mode); the relaunch restores the session as any
  launch does, so no `--restore` argument is registered (the GUI's argument routing does not
  know one before W1-2).
- The first window is created by the app before the restore runs: its throwaway terminal is
  replaced by the saved layout a moment later (CCR W1-7a-2 removes it).

## Test mode

Automatic saves (autosave, full saves, the last `WM_CLOSE`) write nothing in test mode unless
`WMUX_TEST_SESSION_RESTORE=1`; the explicit `session-save` still writes (ADR-12.3). The e2e
suite is `test/e2e/suites/persistence/W1-7a.e2e.ps1`.
