## Design notes
- Plan entry `WP-11-rpc-dispatch` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est. size L
  (11.6 units).
- ADR-3.1-3.7 remainder on top of W1-1a-t: dispatch.zig parses the v2 envelope (W0-P1), checks
  UTF-8/JSON/method, routes by lane (pipe/worker/ui via app.tasks), enforces the 10 s ui deadline
  with the queued->expired CAS, holds mutating ui requests while app.modal.depth > 0, completes
  deferred replies bound to connection generation, and maps Zig errors with errors.fromZig.
  router.zig resolves UUID/ref/index (index = display order from model/logic/display_order.zig) with
  cmux precedence and exact cmux error strings; non-canonical keys fail. The legacy JSON adapter
  runs over the registry and is served both on the sniffed control pipe and on wmux-ipc-<pid>.
  instance.json marker, -alt-<8hex> squatting rule, app/single_instance.zig with app.launch on the
  launch pipe. system.ping/system.capabilities. wmux.debug framework: per-feature
  features/<id>/debug.zig exporting debug_methods aggregated by the registry, plus the core hooks
  ready, app.quit (graceful, waits for WebView2 exit once W1-6c lands), dialogs.list/answer,
  clipboard.get/set (fake), focus_state, layout, type, key, menu.list, menu.invoke (MenuBuilder
  introspection), timers, external_open.list and sounds.list (W0-A4 sinks).
- Depends on: W1-IF, W1-1a-t, W1-2a, W0-A4.
- Derived from the old plan ids WP-03-rpc-server (docs/arch/plan/mapping.md).
- Integrator grant (W1-IF review, 2026-10-17): touches `src/apprt/win32/App.zig` only to call
  `app/logger.start` right after `RuntimeEnv.load` and `logger.stop` in `App.terminate` (no CCR
  needed for the file-logger follow-up); `features/debug/hooks_core.zig` (serves
  `wmux.debug.focus_state`) exposes a hotkeys provider hook (W1-5b registers a callback that fills
  `focus_state.hotkeys`, so W1-5b never edits this file).

## Carried follow-ups
Source: `research/parity/FOLLOWUPS.md` (sections of 2026-10-16 and 2026-10-17) and the known issues of `docs/arch/release-notes/wave-0.md`; read the full entries there before implementing.
- RPC transport OPEN items from W1-1a-t (cf-rpc, merged `304cf53`):
  - set `max_line_bytes` to 16 MiB once a connection is authorized (ADR-3.2); today 1 MiB, with the
    4 MiB pre-authorization cap applied as min(4 MiB, max_line);
  - the ADR-3.1 squatting fallback (`<name>-alt-<8hex>`, recorded in the marker) is not built:
    `PipeServer.start` returns `PipeNameInUse`;
  - `Connection.writeLine` is public but `closePipe` does not take `write_mutex`: event streams
    need a thread-safe push API with a liveness check;
  - admission is not FIFO (new arrivals can take freed slots ahead of pending ones); pending clients
    that disconnect are noticed only at slot grant or at the 15 s cap;
  - the instance limit can be exceeded by one briefly (`gate.release` before `closePipe`), so a
    spare `CreateNamedPipeW` gets `PIPE_BUSY`, retried every 250 ms with a warning per retry;
  - `LaunchPipe.claim`: `on_launch` can run before `claim` returns (document it for
    `app/single_instance.zig`); `PipeClient.readLine` is unbounded: cap it (about 64 KiB) for
    `sendLaunch`;
  - the live tests run only through a standalone command (temporary root file): wire them into a
    build step;
  - the worker-chosen values are recorded in Appendix E D34 (owner decision 2026-10-17 (e)); this
    WP may still tune them through its spec.
- Admit before the legacy pipe-thread `prepare` hook: with a read-only socket control,
  `workspace-new --worktree` still runs `git worktree add` in the pipe-thread `prepare` stage
  (`rpc/server/legacy_pipe.zig`) before the request is refused. Authorization and admission must
  run before `prepare`.
- Start the file logger in `App.init`: call `app/logger.start` right after `RuntimeEnv.load` (it
  starts from the first `Window.init` today, so config-load logs miss `wmux.log`) and
  `logger.stop` from `App.terminate`; move `STATE\logs` under the channel directory once STATE
  is `%LOCALAPPDATA%\wmux\<channel>`; consider a panic hook that flushes the stderr tee (low).
  `App.zig` is frozen and not in this spec: raise a CCR (`docs/arch/ccr/W1-1a-<n>.md`) for the
  two calls.
- Resolve workspace indexes with `model/logic/display_order.zig` (`fromModel` over
  `window.workspaces`/`window.groups`) per ADR-2.4 and AF-22.
- Fill the `Ctx` bodies on the frozen `rpc/types.zig` (`ctx.raw_params`, CCR W0-A3-1, ruling
  D2) under this spec's touches entry.
- Debug hooks (AF-14, plan note 8): `features/<id>/debug.zig` exports `debug_methods`
  (`test_only`), aggregated by `rpc/registry.zig`; this WP builds the framework and the core
  hooks; the feature hooks belong to their owners (`wmux.debug.notices` W1-4b, `web.*` W1-6c,
  `sidebar.*` W1-8b).
- Never reference the app-level registries (`rpc/registry` app instance, the `input/actions.zig`
  app table, the `ui/contrib.zig` lists) from test blocks: that pulls the GTK apprt into the test
  build. Test the generic `Registry(modules)`/`Actions(modules)`.
- The CLI core's Windows-only paths (named pipes, console UTF-16 output, detached launch, registry
  policy reads) were compiled but never run (cf-cli): cover them with Windows e2e once the v2
  server exists (W1-1a, W1-2b).
