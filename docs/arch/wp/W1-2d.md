## Design notes
- Plan entry `WP-12-cli-online-conformance` (`docs/arch/plan/WORKPACKAGES.json`), executor plan,
  est. size L (10.4 units).
- Completes the client half of the control plane end to end: ping/capabilities/rpc against a real
  instance, CMUX_SOCKET_PATH / WMUX_SOCKET_PATH / --socket precedence and the CMUX_SOCKET mismatch
  failure, every CLI-read variable with a WMUX_ twin taking precedence (env.zig), targets.zig
  implementing the cmux target-selection contract once (explicit flags, CMUX_WORKSPACE_ID /
  CMUX_SURFACE_ID defaults only without --workspace/--window, fail-closed exact messages), error
  rendering with Reason/What to do/Details and the version-skew diagnosis on method_not_found (the
  only owner of skew text), retries on overloaded/rate_limited honoring retry_after_ms,
  launch-if-needed commands starting ..\wmux.exe detached and waiting up to the startup timeout for
  the launch pipe, and `cmux <path>` sending app.launch {intent:"open"} without control-socket
  access.
- Depends on: W1-IF, W1-1a, W1-2b, W1-2c.
- Derived from the old plan ids WP-03-rpc-server, WP-05-system-tree-identify,
  WP-08-cli-app-integration (docs/arch/plan/mapping.md).

## Carried follow-ups
Source: `research/parity/FOLLOWUPS.md` (sections of 2026-10-16 and 2026-10-17) and the known issues of `docs/arch/release-notes/wave-0.md`; read the full entries there before implementing.
- CLI framework gaps (shared by W1-2c and W1-2d; the owning spec is named per item, an item in a
  file neither spec owns needs the integrator or a CCR):
  - `platform.zig` gaps (neither spec owns the file): stat/size (the 32 MiB upload message),
    `writeFileAtomic` with flush + the ADR-5.6 sidecar lock + symlink/ACL preservation, a
    stdin-only console check (`diff`, `todo set` and paste block when stdout is redirected), the
    server PID for `AllowSetForegroundWindow` (settings/shortcuts open behind the console) and an
    eager connect for explicit pipes so `grantForeground` works (cli-notify, cli-ws).
  - W1-2d (`main.zig`): the duplicate-command check is asymmetric (misses a later alias against an
    earlier name, and alias against alias).
  - W1-2c (`focus_default.zig`): the usage message must be cmux's `--focus must be true|false`.
  - W1-2d (`launch.zig`): a `new-window` cold start likely opens two windows
    (`launch.ensureControl` lacks the `new_window` intent).
  - The `rename-window` legacy notice names the wrong command; wmux branding in usage errors;
    `resolvePath` handling of `\x` and `D:x` (W1-2c for usage text and `args.zig`; the notice
    table is outside both specs).
  - Ruling D7 output rules (W1-2c/W1-2d conformance): `list-windows`, `current-window`,
    `new-window` and `current-workspace` print UUIDs in text mode without `--id-format`;
    `list-windows --json` is cmux's bare array; reorder and dry-run output follow cmux.
  - Ruling D9 sanitization helper (W1-2c, `output.zig`): text-mode single-line display fields from
    the server or a page get C0/C1 controls except tab replaced with U+FFFD when stdout is a
    console; content outputs and `--json` stay raw (Appendix E D24); families adopt the helper.
- Wire contracts chosen by the CLI and web packages (the RPC WPs must match or renegotiate; W1-2d
  verifies the client half): param names of `workspace.todo.*`, `layout.*`, `wmux.right_sidebar.*`,
  `wmux.diff.open`, `surface.resume.*`, `session.import/export`, `settings.open`, `file.open`,
  `markdown.open`, `comments.list {repo, all}`, `wmux.config.reload`, `app.focus_override.set
  {state}`; `caller` is sent as an object and `identify --no-caller` sends an explicit
  `caller:null`; the assumed result shapes (`pane.list`/`surface.list` rows,
  `system.tree/top/memory`, `window.screenshot` region, `tab.action` `full_width`,
  `workspace.env`, group list keys, delete `{operation, affected}`, `force` on
  `workspace.action`) are listed in FOLLOWUPS.
- Retries on `overloaded`/`rate_limited` honor `retry_after_ms` (values in Appendix E D34:
  250/1000/2000 ms for `overloaded`).
