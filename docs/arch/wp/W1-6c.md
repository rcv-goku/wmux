## Design notes
- Plan entry `WP-12-web-host-bridge` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est. size
  L (1 units).
- ADR-6.1-6.9: one TabContent.web kind hosted in tab, right-sidebar, popup and top-level placements
  (WmuxPanelHost class), PanelKind registry through ui/contrib.zig, one environment under
  STATE/webview2 with the wmux-ui controller profile, environment failure no longer sticky, per-app
  virtual hosts https://<app>.wmux.example/ (DENY_CORS), token file hosts and WebResourceRequested
  data hosts, bridge dispatching PanelKind.on_message then the RPC registry with Origin.in_process
  under the per-kind allowlist (sender identified by controller), panel.* local methods, CSP and
  per-webview hardening, theme push on init and config change, AcceleratorKeyPressed -> input.router
  (W1-5a), lazy controllers and TrySuspend, ProcessFailed reload overlay. BrowserPane moves onto
  WebHost basics. About panel (version, commit, third-party licenses from THIRD_PARTY_LICENSES.md)
  opens as a top-level panel window. Test hooks wmux.debug.web.eval and wmux.debug.window.screenshot
  (PrintWindow); wmux.debug.app.quit now waits (bounded) for ICoreWebView2Environment5
  BrowserProcessExited so the user-data folder is released (S2).
