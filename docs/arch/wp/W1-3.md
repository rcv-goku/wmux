## Design notes
- Plan entry `WP-11-env-identity-jobs` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est.
  size M (7.4 units).
- ADR-3.9 and S4 guidance for W1-3. spawnHooks() returns the protected environment applied after
  every override: CMUX_/WMUX_ WORKSPACE_ID, SURFACE_ID, PANEL_ID, TAB_ID (workspace UUID, cmux
  legacy meaning), PANE_ID, TERMINAL_LIFECYCLE_ID, SOCKET_PATH (pipe from wmux_proto/pipe_name.zig),
  CMUX_SOCKET="" , BUNDLE_ID, BUNDLED_CLI_PATH, SHELL_INTEGRATION_DIR, CMUX_PORT/_END/_RANGE (port
  block per workspace), TERM=xterm-256color unless Ghostty term is set, COLORTERM,
  TERM_PROGRAM(_VERSION); PATH prepends INSTALL/cli (and STATE/shims/<build-id>/agents only while an
  agent integration is enabled; directory created, sentinel .wmux-shims written, stale build-ids
  pruned; wrapper names arrive with W3-2) and keeps the INSTALL append; WSLENV twins; Anthropic auth
  variables removed unless wmux.agents.preserveAuthEnv. Instance job at startup and a nested per-tab
  job (BREAKAWAY_OK only, never KILL_ON_JOB_CLOSE) via PB-platform job.zig; api
  inInstanceJob/surfaceForPid/processIds. Shell-integration fixes: PowerShell 5.1 escape, cmd PROMPT
  with OSC 9;9 and 133, Git Bash detection. Merges after W1-2b so `wmux +verb` inside a terminal
  already resolves to the compatible CLI.

## Carried follow-ups
Source: `research/parity/FOLLOWUPS.md` (sections of 2026-10-16 and 2026-10-17) and the known issues of `docs/arch/release-notes/wave-0.md`; read the full entries there before implementing.
- PB-platform (cf-platform, merged `1152de0`): `platform/tests.zig` (31 tests, live Win32
  included) is in no build step, so the gate never runs it; wire it (through an appendable test
  aggregator) when this WP consumes `platform/job.zig`.
- `job.errorFromWin32` maps `ERROR_FILE_NOT_FOUND` to `ProcessNotFound` for every job call. The
  file `platform/job.zig` is not in this spec's owns (ADR-14.4 gives it to W1-3): ask the
  integrator to extend the spec, or raise a CCR, before changing it.
- `src/termio/Exec.zig` (touches entry): `ReadThread.threadMainWindows` still treats every
  `ReadFile` error other than `OPERATION_ABORTED` (for example `BROKEN_PIPE` or `HANDLE_EOF`
  when the pseudoconsole dies) as `unreachable`, undefined behavior in ReleaseFast: handle the
  pty-closed errors as a clean exit. `processExitWindows` -> `processExitCommon` pushes
  `child_exited` to the surface mailbox with `.forever` while the UI thread joins the termio
  thread in `core_surface.deinit`: use a bounded push or check whether teardown started.
  `stopReadThreadWindows` calls `CancelSynchronousIo`, which cancels any synchronous I/O of the
  thread, not only `ReadFile` (low; at worst one log line lost at shutdown).
- The `env_identity` facade written by W0-A3 (`features/env_identity/api.zig`:
  `adjustDefaultEnv`, `spawnHooks` with `protected_env` and the job) is what this WP fills; the
  job queries `inInstanceJob`/`surfaceForPid`/`processIds` are listed in the kickoff section.
- `src/Command.zig` (touches entry): add `Command.job` to the `PROC_THREAD_ATTRIBUTE_JOB_LIST`
  attribute (the field exists since W0-A3).
