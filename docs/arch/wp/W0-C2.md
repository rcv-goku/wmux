## Design notes
- Plan entry `WP-02-tooling-gates` (`docs/arch/plan/WORKPACKAGES.json`). Implements AF-1, AF-15,
  AF-19 and AF-23 (Appendix F.2, 2026-10-16) in the merged W0-C tooling; the W0-C rules hold
  (`docs/arch/wp/W0-C.md`: PowerShell 7, no external modules, shared code in
  `scripts/lib/WmuxTooling.psm1`, prerequisite-gated steps SKIP with a notice).
- `gate.ps1 -Merge` per merge: fmt, ownership, manifest, debug and ReleaseFast builds, test-fast,
  test-cli, unit filters of the changed areas plus the legacy filters, e2e smoke + legacy +
  regression + the areas named by `# covers:` tags and changed paths, contract tests; budget
  12 min. `-Full` stays for wave ends (N9) and a nightly CI job; `-Batch <a,b>` gates two
  ownership-disjoint WPs on one base (§14.9).
- `scripts/new-wp-specs.ps1` renders `docs/arch/wp/<arch_id>.md` from
  `docs/arch/plan/WORKPACKAGES.json` (owns = files_new + non-frozen files_touched, touches with
  reasons, appends) and fails on placeholders, a files_new path that already exists, a frozen path
  without a touches entry, or two WPs of one plan wave touching the same path outside appends.
  W0-R hand-wrote the four W0 specs (W0-B2, W0-C2, W0-A4, W0-ST); the generator takes over from W1.
- The settings schema becomes a merge-time artifact: `merge=ours` for
  `docs/wmux/schema/wmux.schema.json` in `.gitattributes`; `gate.ps1 -Merge` regenerates it on the
  merged tree and commits `chore(schema)`; check-ownership allows it for every WP (today the gate
  demands a committed, up-to-date golden from each WP).
- AF-15: `fast_tests.zig`, `test_index.zig`, every `**/logic/tests.zig`,
  `src/wmux_cli/logic/tests.zig` and the `proto.zig` re-exports get `merge=union`, with
  check-manifest enforcing one sorted import line per entry. Some of these are frozen
  (`test_index.zig`, `fast_tests.zig`, `model/logic/tests.zig`), and check-ownership accepts a frozen
  path only through a touches entry from wave 1 on: let a declared append to these aggregators
  pass.
- `Test-WmuxWpId` also accepts PB-* ids (`PB-notif`, `PB-web-taskmgr-todo`).
  `docs/arch/manual-checks.md` is the non-blocking ledger of AF-19; check-manifest warns on a
  `# manual:` waiver without a ledger row.
- FOLLOWUPS (2026-10-16):
  - CI runs no Node web tests: the windows-ci.yml glob does not reach `test/web-node/<app>/**`
    (`diff`, `feed`, `notifications`, `settings`, `task-manager`, `todo`, next to
    `test/web-node/markdown.test.mjs`). Run them all in CI.
  - Add `test/web/run.ps1` to a gate tier once PB-web-harness merges (cfleet round 4); until then
    the step is SKIP with a notice.
  - Cross-compile lesson from cfleet round 3: in a `zig test`/`zig build-exe` command line with `-M`
    module flags, `-target` must come before the first `-M`, or zig builds those modules for the
    host. Every cross-compile command the tooling or CI writes follows it (the matching fix of the
    cfleet `make-bundles.ps1` lives outside this repository, with the cfleet operator).
