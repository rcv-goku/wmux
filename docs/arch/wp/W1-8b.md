## Design notes
- Plan entry `WP-12-sidebar-d2d` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est. size M
  (7.4 units).
- ADR-11.1-11.4 with S7 rules (AF-10) on PB-sidebar logic and W1-8a gfx: WmuxSidebar child
  (WS_CLIPSIBLINGS, no class brush, PRESENT_OPTIONS_IMMEDIATELY, explicit GetDpiForWindow,
  synchronous render in WM_SIZE, always render in WM_PAINT, D2DERR_RECREATE_TARGET discards device
  resources), RowContributor/RowBuilder API with the Slot enum extended by legacy_interim,
  program_status and media_activity (AF-12), virtualized smooth scrolling with overlay thumb and
  ensureRowVisible, mouse-up selection, drag reorder with insertion line and Esc cancel, toggle and
  divider-drag width per window, sidebar.fontSize, footer with the new-workspace button and a bell
  button exposing its anchor rect. Layer files are split so later WPs own one each (selection.zig
  W4-5c, drag.zig W4-6a, rename.zig W4-5a, theme.zig W4-4d, hints.zig W1-5b). No visible regression
  (critic issue 9): legacy_contrib.zig renders today's data until the W2 contributors land
  (status/progress/log from the status ext, branch/ports from features/meta probes, bell/exited dot,
  unread badge and a collapsible notification log from legacy_ring), and wmux.sidebar.renderer = gdi
  keeps the old renderer selectable until W2-ST. Test hooks: wmux.debug.sidebar.snapshot (rows,
  geometry, visible, scroll), .click, .hover, .drag, .key and .simulateDeviceLoss.

## Carried follow-ups
Source: `research/parity/FOLLOWUPS.md` (sections of 2026-10-16 and 2026-10-17) and the known issues of `docs/arch/release-notes/wave-0.md`; read the full entries there before implementing.
- The legacy GDI sidebar clips rows past the window now that `MAX_WORKSPACES` is gone; it stays
  selectable (`wmux.sidebar.renderer = gdi`) until W2-ST, so give it at least scrolling or a
  clipped-row indicator.
- `attach`/`detach` facades: `ui/Window.zig` calls `ui/sidebar/mod.zig` and
  `ui/right_sidebar/mod.zig`; since W1-IF they delegate to `api.zig`, so this WP creates the
  child HWND in `ui/sidebar/api.zig` without touching `Window.zig`.
- Test wiring (cf-sidebar): a module rooted at `ui/sidebar/logic/tests.zig` cannot import
  `../../gfx/logic/*`; verify how the merge wired it before adding logic tests.
- Measurer contract: the layout goldens use the fake measurer; the DirectWrite measurer must honor
  `max_lines`, wrap and trim identically.
- `WS_CLIPSIBLINGS` is applied by W0-A4 only to direct children of `WmuxWindow` (explicitly on
  terminals and browser hosts, on `WM_PARENTNOTIFY` for the rest): create the sidebar child with
  it explicitly (S7, AF-10).
