## Design notes
- Plan entry `WP-11-settings-layer` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est. size L
  (11.6 units).
- ADR-5.1-5.5/5.7 app side on top of W0-P2: layer stack defaults < explicitly-set legacy Ghostty
  keys (Config._replay_steps, never defaults) < cmux.json < wmux.json < packs < project files <
  policy, with id-keyed project overrides; atomic refcounted snapshot swap; one watcher thread
  (ReadDirectoryChangesW, 300 ms debounce, content hash, symlink resolution) posting app.tasks;
  onSettingsChanged fan-out and config.reloaded; Ghostty overlay CONFIG/config.ghostty and generated
  STATE/run/settings-overrides.ghostty reload through the existing reload_config path; parse error
  keeps the last good snapshot and raises a ui/notice.zig notice with the first three errors; policy
  reads HKLM/HKCU Software/Policies/wmux (test mode: WMUX_TEST_POLICY_FILE JSON instead of the
  registry), re-read on WM_SETTINGCHANGE("Policy") and every 60 s. Every reload is logged to
  STATE/logs/wmux.log, which the e2e asserts on (wmux.config.reload and the notices debug hook come
  with W1-4b).
- Depends on: W1-IF, W0-P2, W0-A4.
- Derived from the old plan ids WP-03-settings-store, WP-06-config-cli (docs/arch/plan/mapping.md).

## Carried follow-ups
Source: `research/parity/FOLLOWUPS.md` (sections of 2026-10-16 and 2026-10-17) and the known issues of `docs/arch/release-notes/wave-0.md`; read the full entries there before implementing.
- `wmux_proto/settings/specs_manifest.zig` aggregates feature spec files that are still stubs, so
  `specs_manifest.all` is empty and `config get/set` answer "unknown setting"; the layer must
  work with the specs each W1 WP adds (`settings.get` returns spec defaults until the layer
  lands, ADR-5.2).
- Route `settings/legacy_config_files.zig` `openConfigFile`/`openConfigFolder` (direct
  `ShellExecuteW` plus the notepad `CreateProcessW` fallback) through
  `app/dialogs.openExternal`: today only the `open_config` action is intercepted in test mode (in
  `perform_action`), so the sidebar gear and the settings menu bypass `WMUX_TEST_EXTERNAL_SINK`.
- `test-fast` compares the committed `docs/wmux/schema/wmux.schema.json` with the specs
  (`src/build/WmuxSteps.zig`, frozen): a WP that adds a settings spec must regenerate and commit
  the schema on its branch or its local gate fails, although `gate.ps1 -Merge` regenerates it at
  merge. A CCR may move the golden check into the `-Full` contract step.
