## Design notes
- Plan entry `WP-13-rpc-auth-caller` (`docs/arch/plan/WORKPACKAGES.json`), executor plan, est. size
  L (8.4 units).
- ADR-3.8/3.9/3.11: modes off|cmuxOnly (default)|automation|password|allowAll + readOnly with alias
  parsing; cmuxOnly = instance-job membership (W1-3) or creation-time-verified ancestry walk (32
  levels, cached per connection) or a valid _cmux_capability_v1 token (DPAPI-protected secret, HMAC
  per channel, exported as CMUX/WMUX_SOCKET_CAPABILITY); password mode with auth.login and the text
  auth verb (constant-time compare; sources env -> automation.socketPassword -> DPAPI file); env and
  policy overrides (policy accepts only cmuxOnly/off); explicitly-set legacy socket-control honored;
  live mode changes drop unauthorized connections and rebuild the DACL; actionable forbidden
  message. Caller context: params.caller validated, then the client PID's surface job, echoed by
  identify/tree/top. Focus policy: focus_intent allowlist, creation defaults focus:false +
  manual-unread, foreground_grant honored only within 2 s through app/foreground.zig, debug assert
  on focus-generation changes. Text-v1 framework (sniffing, ping, auth, help, ERROR formats).
  socket-status (offline) reports exactly what the server enforces.
- Depends on: W1-IF, W1-1a, W1-3, W1-2d, PB-platform.
- Derived from the old plan ids WP-04-rpc-auth-caller (docs/arch/plan/mapping.md).

## Tests
- unit: rpc: mode alias table; capability HMAC verify; ancestry walk rejects a parent created after
  its child; password compare is constant time (no early exit in code review checklist + test
  vector)
- e2e: default cmuxOnly instance (harness override removed): `cmux ping` from inside a wmux terminal
  succeeds, from the harness process fails with the forbidden message; with CMUX_SOCKET_CAPABILITY
  from the instance it succeeds
