## What
`src/apprt/win32/app/perform_action.zig`, two one-line delegations (ADR-1.6 "every arm is a
one-line delegation"):

- `.pwd` leaves the acknowledged no-op list and becomes
  `.pwd => meta.onPwd(app, target, value),` with `const meta = @import("../features/meta/api.zig");`.
- `quit(self)` (also reached by `.close_all_windows`) calls
  `session_api.onQuit(self);` first, with
  `const session_api = @import("../features/session/api.zig");`.

## Why
- persistence-restore-working-directories (ADR-9.6): "The `.pwd` apprt action (OSC 7 and OSC
  9;9) updates `Tab.cwd` (`features/meta/api.onPwd`, wired by W1-7)". The arm is in the
  exhaustive apprt action switch; no hook or event reaches it from a feature.
- persistence-session-snapshot-autosave (ADR-9.3): the full save on `quit` and
  `close_all_windows` must run while the windows still exist. `quit` posts WM_QUIT; App.run
  then leaves the loop and App.terminate destroys the windows before any feature `deinit`
  runs, and no window message or event fires in between (Window.deinit clears GWLP_USERDATA
  before DestroyWindow). Only the action arm sees the request in time.

## Stub until merged
W1-7a ships `onPwd` (Tab.cwd, the focused tab drives the workspace cwd, session dirty) and
`onQuit` (full save, background writer, flushed by the feature's `deinit`). Without the call
sites the snapshot falls back to the terminal's current pwd (`core_surface.pwd`) and a quit
keeps the last autosave. Once merged: an e2e can assert `clean_exit: true` after `quit`.

## Impact and risks
None for other features; `onQuit` is a no-op in test mode without WMUX_TEST_SESSION_RESTORE.
Merge order: any time after W1-7a.
