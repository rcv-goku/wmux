## What
`test/e2e/suites/cli/W1-2c.e2e.ps1`: the live checks (`--json`/`--id-format`
against an instance, and the live selection part of the four focus-default
Test-Cases) run only when the instance lists the workspace methods they call
(`workspace.list`, `workspace.current`, `workspace.create`) in
`system.capabilities`; otherwise they skip with a message naming W2-1, as they
skip today for a legacy instance.

## Why
The suite gates its live checks on `Instance.Protocol -eq 'v2'`, assuming that
a v2 server also serves the workspace family. W1-1a brings the v2 server (the
cli area runs in its merge gate) but the workspace methods are W2-1's
(Appendix B.1), so after W1-1a these five Test-Cases fail with
`method_not_found` (`--json list-workspaces`, `rpc 'workspace.current'`):

- cli: --json and --id-format work before or after the command; rpc stays raw
- cli: interactive run without agent markers focuses (focus=true)
- cli: CLAUDECODE=1 under a ConPTY stays in the background (focus=false)
- cli: WMUX_FOCUS_NEW=0 overrides the interactive default (focus=false)
- cli: CMUX_FOCUS_NEW=1 makes an agent run focus (focus=true)

No app-side change can fix this short of implementing W2-1's methods, and
W1-1a's spec does not list the suite.
