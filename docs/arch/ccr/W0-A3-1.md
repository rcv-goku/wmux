## What
ADR-3.6's `Ctx` sketch declares a field `params: std.json.ObjectMap` and a method
`pub fn params(self: *Ctx, comptime T: type) Error!T`. Zig does not allow a container field
and a declaration with the same name, so `rpc/types.zig` (frozen since W0-A3) keeps the method
name and calls the field `raw_params`. Amend the sketch to match.

## Why
"Code sketches are binding for names, fields and signatures" (header of ARCHITECTURE.md), but
this one cannot compile. Handlers read typed params through `ctx.params(T)` and
`ctx.param(T, key)` far more often than the raw object, so the method keeps the ADR name.

## Stub until merged
Nothing to stub: the code already uses `raw_params`; only the document differs.

## Impact and risks
W1-1 (owner of the `Ctx` bodies) and every v2 handler: use `ctx.raw_params` for the raw object.
No behavior change.
