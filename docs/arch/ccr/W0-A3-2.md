## What
ADR-3.10's `Event` sketch names an event only by `kind`, an enum built from
`wmux_proto/events_catalog.zig`. The catalog has family entries (`agent.hook.*`, one
entry for every `agent.hook.<HookEventName>`), so `kind` alone cannot say which hook
fired. `model/events.zig` adds one optional field, `name_suffix` (`Stop` for
`agent.hook.Stop`, null for exact names), the constructor `Event.ofFamily(family, suffix,
source)` and `Event.name(buf)`, which writes the concrete name. Amend the sketch to match.

## Why
FOLLOWUPS.md (cf-p4) records that `agent.hook.<HookEventName>` cannot be emitted with
the ADR-3.10 fields and asks for a change to `model/events.zig` (owner: W0-A3). The
stream and the durable log (W2-4) must write the concrete name, as cmux does, and the
agents platform (W3-1, `wmux.agent.hook`) emits one event per hook. "Code sketches are
binding for names, fields and signatures" (header of ARCHITECTURE.md), so the added
field needs the document change.

Plus an Appendix F.2 history row.

## Stub until merged
Nothing to stub: the code already has the field; only the document differs. The unit
test "unit: model: events of a family carry the suffix in their name" covers it.

## Impact and risks
W2-4 writes `ev.name(&buf)` (not the catalog entry name) into frames and the log; W3-1
emits hook events with `Event.ofFamily("agent.hook.*", hook_name, agent)`. No behavior
change.
