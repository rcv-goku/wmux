## What
`test/e2e/WmuxTest.psm1`, `Get-WmuxScreenshot`: take the app-side capture
(`wmux.debug.window.screenshot`) only when the instance lists that method in
`system.capabilities`; otherwise use the harness capture
(`Save-WmuxWindowCapture`, the path legacy instances use today), which also
computes `Placement` and `TerminalCheck`.

Optional, same file, in the same change (no test depends on them):
- `Save-WmuxFailureSnapshot`: the same rule for the failure screenshot (it
  already catches the error, so today it only loses the image).
- `Wait-WmuxInstanceReady`: list the pipes again after the v2 readiness probe
  succeeds before setting `LegacyPipe`; the list is taken before the probe, so
  `LegacyPipe` stays empty when the app was still in `App.init` (the legacy
  pipe starts right after the control pipe).

## Why
W1-1a makes every instance speak v2, so the harness switches to its v2 paths.
`Get-WmuxScreenshot`'s v2 path calls `wmux.debug.window.screenshot`, which is
W1-6c's hook (Appendix B.3) and does not exist yet, so
`suites/regression/w0-regression.e2e.ps1` "the hidden window stays off the
user's screen and its terminal renders" fails with `method_not_found` in every
merge gate after W1-1a. Even once the method exists, that path hard-codes
`TerminalCheck = 'none'`, which the test turns into a failure; the harness
capture computes the check. No app-side change can fix this, and W1-1a's spec
does not list the harness (W0-B2 is done; no W1 WP owns it).

Verified on `wp/W1-1a-v2-control-plane` (Debug build, 2026-10-17) with the
diff applied to the worktree and reverted afterwards (never committed):
`pwsh test/e2e/run.ps1 -Suite regression -NoRetry` → W0-ST 2/2 passed,
w0-regression 12 passed and 1 skipped (the same skip as on master: "W0-A4:
the cloaked hidden window captures, but its terminal area is blank"). Without
the diff the same run fails that Test-Case with `rpc
'wmux.debug.window.screenshot' failed: method_not_found: Unknown method`.

## Stub until merged
Nothing in the app can stand in. The integrator applies the diff before (or
with) the W1-1a merge; until then `scripts/gate.ps1 -Merge -Wp W1-1a` reports
exactly one e2e failure (the Test-Case above). W1-6c's screenshot hook should
make the v2 path compute `TerminalCheck` from the app's PNG, or keep the
harness capture.

## Impact and risks
Harness only; legacy instances are unaffected (they take the harness capture
already). One extra `system.capabilities` call per screenshot. W1-6c owns the
follow-up for the app-side capture.
