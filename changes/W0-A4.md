# W0-A4: spike fold-ins, test isolation and sinks, file logger, S7, model check

Mostly invisible to users. Two visible changes: wmux now writes a log file, and child windows
clip their siblings.

- Log file: every log line also goes to `STATE\logs\wmux.log` (`WMUX_STATE_DIR\logs`, else
  `%LOCALAPPDATA%\wmux\logs`) with a UTC timestamp. The file rotates to `wmux.log.1` at 8 MiB.
  `WMUX_LOG=debug|info|warn|error|off` sets the level (default `info`); stderr output is
  unchanged.
- Hidden test instances (`WMUX_TEST_HIDDEN`, spike S2): the UI thread's WH_CBT hook now also
  refuses every `SetFocus` whose top-level window is not already active (the S2 "gate"
  policy), so no focus call can activate a hidden window. The cloaked placement on the
  primary work area, the `DWMWA_CLOAKED` check with the -32000 fallback, and the activation
  block were already in place from W0-A1. A unit test pins the clamp on a 1024x768 display.
- Test isolation (`WMUX_TEST_MODE`): window placement is neither restored nor saved, and
  closing a window saves no session, unless `WMUX_TEST_SESSION_RESTORE=1`. The update check
  was already off; its `update_check_at` file now goes through `app/paths.zig` like every other
  state path. The explicit `session-save` command still writes `session-state.json`.
- Test sinks (AF-16): in test mode `open_url`, `open_config` and the update balloon's link
  start nothing and append a JSON line to `WMUX_TEST_EXTERNAL_SINK`. The bell (and any
  `MessageBeep`/`PlaySound`) plays nothing and appends to `WMUX_TEST_SOUND_SINK`. File dialogs
  answer from `WMUX_TEST_FILE_DIALOG` (a path, or cancel when it is unset).
- `app/dialogs.zig` is the only entry for `MessageBoxW`, `IFileDialog`, `ShellExecuteW`,
  `MessageBeep` and `PlaySoundW`. `app/modal.zig` keeps only the modal-depth counter.
- S7: terminal and browser-host windows get `WS_CLIPSIBLINGS`. The top-level window adds it to
  every other direct child on `WM_PARENTNOTIFY`.
- S1: `wmux.exe` (debug and ReleaseFast) imports neither `runtimeobject` nor `combase`, so
  `SharedDeps.zig` needed no change.
- Model (AF-22): the ADR-2.3 group and pin fields match the spec. New
  `model/logic/display_order.zig` computes the workspace display order that W1-1a uses for
  indexes: pinned entries first; each group expands in place at its anchor, pinned members
  first.
