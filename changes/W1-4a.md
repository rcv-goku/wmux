# W1-4a: settings layer

- wmux reads settings from the shared `~/.config/cmux/cmux.json` and `wmux.json` (JSONC), with packs, a project file found upward from the working directory, explicitly set legacy Ghostty keys below them and Group Policy (`HKLM`/`HKCU\Software\Policies\wmux`) above them.
- Settings files reload live about 300 ms after a save, including symlinked files; every reload is logged in `STATE\logs\wmux.log` with its revision and the changed keys.
- A syntax error in a settings file keeps the previous settings and shows a notice with the first three errors and an Open button; invalid values fall back to the next layer.
- The Ghostty configuration now also loads `CONFIG\config.ghostty` and the generated `STATE\run\settings-overrides.ghostty` (e.g. `terminal.copyOnSelect` -> `copy-on-select`); edits to Ghostty config files reload it automatically, and Ghostty config errors show a notice.
- Reload Configuration (Ctrl+Shift+,) reloads both the Ghostty config and the JSON settings.
- Opening the config file or folder goes through the external-launch path, so test instances record it instead of starting an editor.
