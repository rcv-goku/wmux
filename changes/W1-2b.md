# W1-2b: wmux.exe CLI relay, legacy +verbs through the CLI, release staging

- `wmux.exe` relays CLI-shaped calls to `cli\cmux.exe`: cmux commands
  (`wmux.exe list-workspaces --json`), the cmux global options and every legacy wmux `+verb`
  run the console CLI with the same handles and exit code; piped and redirected calls print
  their output, and a GUI `wmux.exe` started from a console attaches to it. Ghostty's own
  `+actions` (`+version`, `+list-themes`, `+ssh`, `+hooks`, ...) still run inside `wmux.exe`,
  and `cli\cmux.exe` relays them there (`cmux +version` returns `wmux.exe`'s exit code).
- Legacy `+verbs` keep their exact output through `wmux.exe` and through `cli\wmux.com`: the
  CLI sends the old legacy JSON command over `\\.\pipe\wmux-ipc-<pid>` and prints the reply
  byte for byte, with the old argument meanings (`+status set <text>`, `+status progress 0-100`
  and `clear`, `--tab`/`--pane`/`--workspace` anywhere, `+notify next`, `+browser --id/--tab/
  --split`, `+capture-pane --file`). Without any legacy pipe a `+verb` falls back to its cmux
  command (ADR-4.11).
- `+verb --help` (decided by W1-2b): the removed verbs keep the legacy text,
  `error: ActionHelpRequested` with exit code 1, with or without a running instance; the
  Ghostty actions keep their own help, and the cmux commands have `wmux <command> --help`.
- The old in-process clients in `src/cli` (`workspace`, `tab`, `send`, `notify`, `surface`,
  `split`, `status`, `log`, `read_screen`, `capture_pane`, `session`, `browser`, `new_window`,
  `toggle_quick_terminal`) are removed; `agent_ipc.zig` stays for `+ssh --workspace` until
  W6-1a, `hooks.zig` until W3-3a.
- Release staging (`dist/windows/release.ps1`) stages `cli\cmux.exe`, `cli\wmux.exe`,
  `cli\wmux.com`, `cli\posix\{cmux,wmux}` (LF launchers running `..\cmux.exe`) and
  `share\wmux\**` (web apps, settings schema) next to the existing payload; new options
  `-Prefix`, `-StageDir`, `-OutputDir`, `-NoInstaller`, `-Smoke` and `-NoDownload`. The installer
  installs `cli\` (still never touching PATH).
- New contract check `test/contract/release-smoke.ps1` (gate `-Merge`/`-Full`): ReleaseFast
  build, staging, a silent install of a smoke installer (own AppId, no shortcuts) to `%TEMP%`
  when Inno Setup is available, and the installed CLI and relays.
- Docs: `docs/wmux/cli/legacy.md`.
