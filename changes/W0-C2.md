# W0-C2: tiered merge gate, WP spec generator, merge-time artifacts, manual-check ledger

Tooling only (AF-1, AF-15, AF-19, AF-23); no user-visible change.

- `scripts/gate.ps1` gets tiers: `-Merge` per merge (budget 12 min, `summary.json` with step
  durations, total seconds and `within_budget`; area unit filters always plus the legacy
  filters; one e2e run of smoke + legacy + regression + the affected areas, with missing
  suites skipped; the settings schema regenerated and committed as `chore(schema)`; the
  ReleaseFast build runs in the background beside the other steps), `-Batch <a>,<b>` for
  two ownership-disjoint WPs on one base, `-Full` for wave ends and the nightly CI job (now
  with the unfiltered `zig build test` by default), and a `web` step that runs
  `test/web/run.ps1` when `src/web` or `test/web` changed.
- `scripts/new-wp-specs.ps1` renders `docs/arch/wp/<arch_id>.md` from
  `docs/arch/plan/WORKPACKAGES.json` and refuses placeholders, existing `files_new` paths,
  frozen paths without a touches entry and same-wave overlaps outside appends.
- `.gitattributes`: `merge=union` for `fast_tests.zig`, `test_index.zig`, every
  `**/logic/tests.zig`, `src/wmux_cli/logic/tests.zig` and `proto.zig`; `merge=ours` for
  `docs/wmux/schema/wmux.schema.json` (the gate defines the `ours` driver).
- `scripts/check-manifest.ps1` enforces one sorted import line per aggregator entry (five
  `logic/tests.zig` indexes were re-sorted, no line dropped) and warns about a `# manual:`
  waiver without a row in the new ledger `docs/arch/manual-checks.md`.
- `scripts/check-ownership.ps1` allows the schema, ledger rows and sort-only aggregator edits
  for every WP, accepts a declared append to a frozen aggregator, and checks another branch
  with `-Head`. WP ids may be `PB-*`. The frozen list covers the core files of plan note 6.
- CI: nightly `gate.ps1 -Full` job; a Node job runs every `test/web-node/**/*.test.mjs`.
