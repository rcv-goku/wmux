# W1-6b: WebView2 bindings completed

Internal groundwork for the web panels, browser security prompts, downloads, remote browser egress and browser lifecycle work. No user-visible change yet.

- `platform/webview2.zig` now binds every WebView2 interface later work packages need, from WebView2 SDK 1.0.4258.31: all slots of ICoreWebView2 (no more padding), ICoreWebView2_2 to _16, Controller2-4, Settings to Settings8, Environment2-10, ControllerOptions, the event-argument and helper interfaces (downloads, cookies, context menus, permissions, script dialogs, new windows, web resources, client and server certificates, basic authentication, process info, profile, print settings) and a handler factory for each of the 56 callback interfaces they use.
- A comptime check compares every bound IID, slot name, slot index and slot count against a table taken from the SDK's `WebView2.h`, so a mistake in a binding fails the build.
- New helpers: `qi(T, obj)` (QueryInterface through `T.IID`, null on older runtimes), `retain` for borrowed callback interfaces, `Handler1` for one-argument completions, a host-implemented `EnvironmentOptions` (AdditionalBrowserArguments, Language, TargetCompatibleBrowserVersion, AllowSingleSignOnUsingOSPrimaryAccount) and `Loader.createEnvironmentWithOptions`.
- Existing callers keep compiling unchanged; the file is frozen from now on (changes go through a CCR).
