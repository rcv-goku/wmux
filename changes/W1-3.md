# W1-3: protected terminal environment, PATH and WSLENV, jobs, shell integration

- Every terminal now carries the cmux identity environment: `CMUX_WORKSPACE_ID`,
  `CMUX_SURFACE_ID`, `CMUX_PANEL_ID`, `CMUX_TAB_ID` (the workspace id, cmux's legacy meaning),
  `CMUX_PANE_ID`, `CMUX_TERMINAL_LIFECYCLE_ID`, `CMUX_SOCKET_PATH` (the control pipe),
  `CMUX_SOCKET` (empty), `CMUX_BUNDLE_ID`, `CMUX_BUNDLED_CLI_PATH`, `CMUX_SHELL_INTEGRATION_DIR`
  and the per-workspace port block `CMUX_PORT`/`CMUX_PORT_END`/`CMUX_PORT_RANGE`, with `WMUX_*`
  twins. They are applied last, so the Ghostty `env` setting or a workspace env cannot override
  them.
- `TERM` is `xterm-256color` unless the Ghostty `term` key is set (WSL and ssh hosts lack the
  `xterm-ghostty` terminfo); `COLORTERM`, `TERM_PROGRAM` and `TERM_PROGRAM_VERSION` are
  protected too.
- `INSTALL\cli` is first on `PATH` inside wmux terminals, so `wmux` and `cmux` run the bundled
  CLI; `WSLENV` forwards the ids to WSL processes.
- Inherited `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`,
  `CLAUDE_CODE_USE_BEDROCK` and `CLAUDE_CODE_USE_VERTEX` are removed from terminals unless
  `wmux.agents.preserveAuthEnv` is true. New settings `automation.portBase` (9100) and
  `automation.portRange` (10).
- wmux runs in an instance job and starts each terminal in its own tab job (never
  kill-on-close): the base for socket access checks, caller identification and per-surface
  process lists. Closing a tab never kills processes through the job.
- `STATE\shims\<build-id>\agents` is created for the agent wrappers of W3-2; stale build-id
  directories are pruned.
- Shell integration: Git Bash and MSYS `bash.exe`/`zsh.exe` are detected (the System32 WSL
  launcher is not); cmd.exe with its default prompt gets a prompt that reports the working
  directory (OSC 9;9) and marks prompts (OSC 133); the PowerShell integration works in Windows
  PowerShell 5.1, and `powershell.exe -NoProfile` in the `command` setting now really skips the
  profile.
- Fixes: a terminal whose pseudoconsole dies no longer hits `unreachable` in its read thread
  (undefined behavior in release builds); closing a terminal while the app mailbox is full can
  no longer deadlock on the child-exited message; job errors are mapped per Win32 call.
- Docs: `docs/wmux/features/env_identity/W1-3.md`.
